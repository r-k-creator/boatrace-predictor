## 3. GitHub Actions cronの間引き問題の発見と対策

- **発見**: `deadline_reminder.yml`/`odds_fetch.yml`(いずれも5分おきcron)が、実際には
  1日あたり本来168回のところ約4回程度しか発火しないことが判明(GitHub Actions側の
  scheduled cronはbest-effortであり、頻度を問わず正確な実行を保証しない)。1日1回の
  `morning_program.yml`ですら約2〜5.5時間遅延する事例を複数確認。
- **対策(PR #3, #4)**: `deadline_reminder.yml`・`odds_fetch.yml`の`workflow_dispatch`に
  `race_key`入力(例"17-7")を追加。指定時は時間窓判定を一切行わず、そのレースだけを
  即時処理する。外部スケジューラ(Windows タスクスケジューラ、`~/.boatrace-dispatch`)が
  締切5分前ちょうどに1回だけ呼び出す新方式に対応。実際にworkflow_dispatchを起動して
  PAT権限・コミット&pushまでの完走を確認済み。
- **旧cronの無効化(PR #5、2026-09-28)**: 新方式が本番実証されたのを受け、
  `deadline_reminder.yml`の`schedule:`トリガーをコメントアウトで無効化(削除ではない、
  `workflow_dispatch`は維持)。旧cronが遅れて発火すると「オッズ未取得の通知」を
  先に送信済み記録してしまい、正しい通知がスキップされる実害(2026-09-28 13:40戸田7R)が
  出たため。`odds_fetch.yml`側のcronは重複送信の問題が無いため維持。

## 5. データ不具合の発見・修正

- **結果未確定データの永続スキップバグ**: `fetch_results.py`が「日付が存在するか」だけで
  スキップ判定していたため、API側が結果未確定の空データを返した日が永久にスキップされる
  不具合。`read_existing_valid_dates`/`remove_rows_for_date`を追加して修正。
  `evaluate_bets.py`も候補に1件でも結果未確定があれば当日の収支評価全体をスキップするよう修正。
- **`payouts.win`欠損への対応**: API側で単勝払戻配列だけが空になるケースに対し、
  `racer_place_number`から1着艇を補完するフォールバックを追加。
- **09-20/09-29分のbets_evaluations.csvバックフィル**: 結果未確定によりスキップされた
  2日分について、git履歴上の候補一覧+`predictions/`から`generate_bets.py`で当時と同じ
  ロジックによりrank/budget/betsを再構成し、`evaluate_bets.py`を手動実行して追記

  09-21分は35レース分の結果未確定が残り未解消。
